# Lampy MVP 功能需求

> 文档状态：MVP 目标需求基线  
> 更新日期：2026-09-22  
> 适用范围：微信小程序现有能力演进，以及计划中的 iOS App  
> 优先级：P0 = MVP 必须；P1 = MVP 验证期需要；P2 = 后续版本。  
> 实现状态：已实现仅表示当前仓库存在相应能力，不代表已通过微信开发者工具或 iPhone 真机验收。

## 1. 范围与术语

### 1.1 MVP 闭环

```text
创建或恢复草稿
    → 写、拍、选或录
    → 本地可靠保存 Moment 与 Asset
    → 首页看见最近生活
    → 历史按时间浏览
    → 打开同一条只读详情
    → 可选地交给家庭
```

个人记录闭环必须先稳定，家庭共享不能以牺牲本地数据安全为代价。

### 1.2 核心术语

| 术语 | 功能语义 |
|---|---|
| Moment | 用户确认保留的一条生活记录 |
| Asset | 独立保存的图片、音频或未来媒体资产 |
| Transmission | 一次明确的传递/接收过程，不是 Moment 布尔字段 |
| Draft | 尚未确认保存、但应可恢复的 Moment 编辑状态 |
| Personal | 仅所有者可访问的范围 |
| Family space | 用户创建并通过邀请加入的私人共享空间，不代表平台验证真实亲属关系 |
| Occurred time | 事情实际发生的时间，允许未知或较低精度 |
| Recorded time | 内容进入 Lampy 的时间，必须存在 |
| Imported time | 外部素材被导入的时间，不能冒充发生时间 |

产品展示名称仍可能调整，但上述领域语义不随文案变化。

## 2. 角色与权限

### FR-ROLE-001 本地个人用户

- **优先级**：P0
- 未接入账号系统时使用当前 `local-user` 过渡身份。
- 用户可以创建、查看自己的 Moment。
- UI 不得暗示 `local-user` 已经是可跨设备识别的真实账号。

### FR-ROLE-002 已认证个人用户

- **优先级**：P1，家庭共享前置条件
- 系统必须为用户提供稳定身份。
- 身份认证方式待技术与合规方案确认。
- 登录失败不得删除本地 Moment 或草稿。

### FR-ROLE-003 家庭成员

- **优先级**：P1
- 成员资格只能通过有效邀请和用户主动接受建立。
- Lampy 不验证血缘，不在领域中把成员资格命名为“已验证亲属”。
- 成员必须能查看自己的角色、退出空间并管理个人可见内容。

### FR-ROLE-004 家庭创建者/管理员

- **优先级**：P1
- 可以创建家庭空间、生成邀请、撤销邀请和移除成员。
- 管理权不自动赋予查看成员所有个人 Moment 的权限。
- 管理员不能替其他成员同意共享，也不能冒充其他成员创建内容。

## 3. 创建与草稿

### FR-CREATE-001 自然开始记录

- **优先级**：P0
- 用户进入创建页后无需先选择文字、图片或声音模板。
- 用户可以从空白状态直接写、拍、选或录。
- 创建页不得以标准字段标题和按钮矩阵组织为表单。
- 用户未输入任何内容时可以安全退出，不生成 active Moment。

### FR-CREATE-002 文字记录

- **优先级**：P0
- 支持手动输入一段文字。
- 纯文字可以独立保存为 active Moment。
- 保存前后必须保留用户原始表达，除非用户主动编辑。
- 系统不得自动润色、总结或补全正式内容。

### FR-CREATE-003 图片记录

- **优先级**：P0
- 支持现场拍摄和从系统相册选择。
- 单条 Moment 最多三张图片。
- 支持纯图片 Moment。
- 用户可以在保存前删除某张图片。
- 超过三张时应在用户选择前或选择后立即给出明确反馈，不得静默丢弃。
- 图片应作为独立 Asset 持久化，Moment 只保存 Asset ID。

### FR-CREATE-004 音频记录

- **优先级**：P0
- 支持录制、停止、试听、重新录制和删除。
- 单条 Moment 在 MVP 中最多一段音频。
- 支持纯音频 Moment。
- 默认交互采用点击开始、点击结束，不把长按作为唯一方式。
- 录制中必须明确显示正在录制和已录时长。
- 不自动播放。
- 临时录音必须在保存或草稿持久化前进入应用控制的可靠位置。

### FR-CREATE-005 混合内容

- **优先级**：P0
- 一条 Moment 可以包含文字、最多三张图片和最多一段音频。
- 媒体顺序必须确定并可重复投影。
- 任一媒体失败不影响其他内容保存和展示。

### FR-CREATE-006 草稿自动保存

- **优先级**：P0
- 输入文字、选择图片或完成录音后应自动更新草稿。
- 用户返回、切后台、页面卸载或 App 被杀死后，草稿应可恢复。
- 同一草稿恢复后沿用同一 ID，不生成重复草稿。
- 草稿写入失败必须提示，但不得清除仍在内存或文件中的内容。

### FR-CREATE-007 草稿恢复

- **优先级**：P0
- 再次进入创建页时，如果存在有效草稿，应提示继续或放弃。
- 文案应说明其中包含哪些内容，而不是使用技术术语。
- 放弃草稿是破坏性操作，必须由用户明确确认。
- 放弃只删除应用确认拥有且不再被引用的草稿文件。

### FR-CREATE-008 保存 Moment

- **优先级**：P0
- active Moment 至少包含非空文字或一个合法 Asset。
- 保存操作必须幂等，重复点击不能产生重复 Moment。
- 保存期间可以防止重复操作，但不能锁死页面退出和系统中断恢复。
- 只有 Moment 与 Asset 引用均持久化成功后才能显示保存成功。
- 保存成功后清除对应草稿，不影响其他 Moment。

### FR-CREATE-009 保存失败

- **优先级**：P0
- 保存失败时保留草稿、媒体和可重试状态。
- 不得写入假成功 Moment。
- 不得删除或覆盖已有数据。
- 用户应看到直接、可行动的提示，例如“暂时没保存好，可以再试一次”。

### FR-CREATE-010 时间输入

- **优先级**：P0
- 新建时可以以当前时间作为用户确认的发生时间默认值，但用户应能调整或标记未知。
- 导入时间和媒体 metadata 只能作为线索，不能自动成为发生时间。
- 支持 exact、day、month、year、unknown 精度。

### FR-CREATE-011 情绪语境

- **优先级**：P1
- 情绪完全可选，不影响保存资格。
- 不采用正负分数、积极率或连续打卡。
- 至少能够表达平静、复杂、不确定或“说不清”的状态。
- 情绪不得影响排序、视觉尺寸或推荐。
- 最终交互和词汇表待产品语言阶段确认。

### FR-CREATE-012 significance

- **优先级**：不进入 MVP
- 创建页不得要求用户解释“为什么重要”。
- 现有领域字段为兼容保留，MVP 页面不采集、不以缺失为错误。

## 4. 权限与系统资源

### FR-PERM-001 按需请求权限

- **优先级**：P0
- 只有用户触发拍照、选图或录音时才请求相应权限。
- 启动 App 或进入首页时不得请求相机、相册或麦克风权限。

### FR-PERM-002 权限拒绝

- **优先级**：P0
- 拒绝某项权限不应使整个创建页失败。
- 用户仍可使用文字和其他已授权能力。
- 对永久拒绝提供系统设置指引。
- 不反复弹窗施压。

### FR-PERM-003 相册有限访问

- **优先级**：P0（iOS）
- 支持 iOS 有限照片访问。
- 不要求完整相册权限才能导入用户主动选择的照片。

### FR-PERM-004 音频中断

- **优先级**：P0
- 来电、系统音频会话变化、切后台或设备变化导致中断时，停止或安全结束当前录音。
- 已经生成的有效音频不得因页面状态变化被静默删除。
- 页面恢复后应说明录音状态。

## 5. 首页：最近生活

### FR-HOME-001 首页职责

- **优先级**：P0
- 首页优先呈现最近生活留下了什么。
- 首页不是推荐流、公开动态流或统计仪表盘。
- 历史整体积累交给历史页承担。

### FR-HOME-002 首次使用

- **优先级**：P0
- 真实空库展示自然空状态和记录入口。
- 不 seed 模拟 Moment、Light、Transmission 或家庭成员。
- 空状态不暗示用户已经错过记录。

### FR-HOME-003 最近内容组合

- **优先级**：P0
- 支持一条记录、同一天多条、连续多天及长时间未记录。
- 支持文字、图片、音频和混合 Moment。
- 同一天记录可以形成自然组合，但仍能精确进入每个 Moment。
- 排布差异必须由内容类型、时间与尺寸决定，不使用随机数制造生活感。

### FR-HOME-004 很久没有记录

- **优先级**：P0
- 保留最近真实内容，不显示“断更”“连续天数归零”等责备信息。
- 记录入口保持可见，但不通过弹窗和倒计时催促。

### FR-HOME-005 大量历史

- **优先级**：P0
- 首页不加载完整历史。
- 最近内容数量和分页/窗口策略由 Projection 决定。
- 一年后首页仍保持安静，不因累计数量变成密集信息流。

### FR-HOME-006 首页状态

- **优先级**：P0
- 明确区分 loading、ready、empty 和 error。
- 读取失败不能显示为空，也不能写入 mock。
- `onShow`/前台恢复可以刷新 Projection，但不能重播完整 Splash。

## 6. 历史浏览

### FR-HISTORY-001 日浏览

- **优先级**：P0
- 展开某一自然日内的全部 active Moment。
- 同一天内容按确定性规则排序。
- 没有记录的日期保持安静，不显示失败或责备提示。

### FR-HISTORY-002 月浏览

- **优先级**：P0
- 用户能感知一个月中记录的疏密。
- 月视图不能只是标准 Tab 下的等距卡片列表。
- 可以自然进入某一天，并在返回时保持原位置。

### FR-HISTORY-003 年浏览

- **优先级**：P0
- 用户能感知一年整体的生活纹理和时间分布。
- 可以从年进入月、从月进入日、从日进入 Moment。
- 没有记录的月份不应被标记为失败或缺失任务。

### FR-HISTORY-004 时间边界

- **优先级**：P0
- 日/月/年以查看者时区的自然时间边界计算。
- 优先使用 occurredAt。
- occurredAt 缺失时可以使用 recordedAt 作为展示回退，但必须标记为回退，不得伪造发生时间。

### FR-HISTORY-005 位置连续性

- **优先级**：P0
- 从历史进入详情并返回时，恢复原视图、时间范围和滚动/焦点位置。
- App 重启后是否恢复历史位置属于 P1。

### FR-HISTORY-006 性能

- **优先级**：P0
- 大量历史不得一次渲染全部媒体原图。
- 使用缩略图、惰性加载和可控窗口。
- 性能优化不能改变 Moment/Asset 领域身份。

## 7. Moment 详情

### FR-DETAIL-001 精确打开

- **优先级**：P0；当前仓库已实现基础能力
- 页面只通过 Moment ID 请求详情 ViewModel。
- 找不到指定 Moment 时显示 not-found，不得回退到第一条或其他记录。
- 读取详情不修改 revision 和持久化内容。

### FR-DETAIL-002 内容组合

- **优先级**：P0
- 支持纯文字、单图、最多三图、纯音频和混合内容。
- 图片保持原始比例，不强制裁成统一商品缩略图。
- 文字、图片与声音的顺序和层级必须确定。

### FR-DETAIL-003 日期展示

- **优先级**：P0；当前仓库已实现基础能力
- 支持 exact、day、month、year 和 unknown。
- 使用 recordedAt 回退时显示“记录于……”，而不是伪装成发生日期。

### FR-DETAIL-004 图片状态

- **优先级**：P0；当前仓库已实现单图基础能力
- 图片可用时可查看大图。
- 某张图片缺失时显示局部缺失状态，其他内容继续展示。
- 不得因加载错误写回 Asset 为永久 missing，除非经过独立可靠的存储判断。

### FR-DETAIL-005 声音状态

- **优先级**：P0；当前仓库已实现基础播放状态机
- 提供播放、暂停和可用时长。
- 不自动播放。
- 视觉表达应服务“听见当时”，但仍满足明确可操作性。
- 播放失败只影响本次播放状态，不删除 Moment 或 Asset。
- 切换、结束、错误和页面释放时正确销毁音频会话；旧事件不能覆盖新会话。

### FR-DETAIL-006 来源

- **优先级**：P1
- 能区分用户创建、导入和收到。
- legacy received 必须保留 legacy 标记，不得声称已发生真实线上送达。
- 家人协助记录的展示语义必须在家庭模型确定后补充。

### FR-DETAIL-007 页面状态

- **优先级**：P0；当前仓库已实现基础状态
- 使用 loading、ready、not-found、error 等互斥状态。
- 技术错误进入日志，不把堆栈或存储 key 暴露给用户。

### FR-DETAIL-008 只读边界

- **优先级**：P0
- MVP 详情页保持只读。
- 编辑、删除、归档等操作如后续加入，必须通过领域命令，不得直接修改页面 ViewModel。

## 8. 家庭空间与邀请

> 本节为 P1 MVP 目标。当前仓库尚未实现，不得用现有 nearby 或本地 pass 模拟完成。

### FR-FAMILY-001 创建家庭空间

- 一个稳定身份用户可以创建受限数量的家庭空间。
- 空间有稳定 ID、显示名称、创建者和状态。
- 名称不证明真实家庭身份。

### FR-FAMILY-002 邀请

- 邀请包含不可猜测 token、创建者、目标空间、创建时间和过期时间。
- 邀请可以撤销、过期，并限制使用次数。
- 接受前显示邀请人和空间，不自动加入。
- 转发泄露的邀请必须可失效。

### FR-FAMILY-003 成员资格

- Membership 独立于 User 和 Moment。
- 至少表达 active、left、removed 等状态及生效时间。
- 成员退出或被移除后，新的访问请求必须立即重新计算权限。
- 历史内容是否保留副本由接收/快照语义决定，不能由 UI 猜测。

### FR-FAMILY-004 有限关系网络

- 不提供陌生人搜索、附近、随机匹配、公开家庭列表或关注。
- 限制单个家庭成员数、单账号家庭数和邀请频率。
- 具体上限是开放产品决策。

### FR-FAMILY-005 成员安全操作

- 成员可以退出家庭、屏蔽成员和举报内容。
- 管理员可以移除成员。
- 退出和移除必须说明对未来内容及既有接收副本的影响。
- 平台可以冻结邀请或共享能力，但不得因此删除原始个人 Moment。

### FR-FAMILY-006 老人协助记录

- 产品必须区分执行记录的人与内容主要关于的人。
- 家人协助导入或录制时，不得把协助者创建的内容伪装为老人本人创建。
- 是否需要“内容主体”字段及其授权证据，留给家庭领域模型确定。

## 9. 家庭分享与 Transmission

### FR-SHARE-001 分享范围

- **优先级**：P1
- 用户可以为自己的 active Moment 选择“仅自己”或指定家庭。
- 默认范围必须明确，不得因加入家庭自动公开全部个人历史。
- 修改默认值不追溯改变旧 Moment，除非用户明确批量授权。

### FR-SHARE-002 独立 Transmission

- **优先级**：P1
- 分享通过独立 Transmission/授权流程表达。
- Moment 上不得新增 `isShared`、`isFamily` 等布尔值代替分享历史。
- Transmission 需要明确 sourceMomentId、sourceRevision、sender、目标范围、状态和时间。

### FR-SHARE-003 快照语义

- **优先级**：P1，待领域决策
- 发送时必须绑定确定的 Moment revision。
- 发送后的源 Moment 修改不得无声改写已经收到的内容。
- 接收者获得独立副本还是受控共享引用，必须在实现前形成正式规格。

### FR-SHARE-004 幂等与失败

- **优先级**：P1
- 重复点击或网络重试不得生成多次逻辑送达。
- 发送失败保持可重试，不把失败标记成 sent/received。
- 页面失败不能删除源 Moment。
- 当前仓库 `sent` 只表示本地意图，不能用于真实家庭送达 UI。

### FR-SHARE-005 撤回与权限变化

- **优先级**：P1，待领域决策
- 撤回必须有明确状态和时间，而不是删除 Transmission。
- 已产生接收副本后能否撤回，需要结合所有权、隐私和用户预期单独决定。

## 10. UGC 与内容安全

### FR-SAFETY-001 共享前检查

- **优先级**：P1，家庭共享上线前必须
- 进入家庭可见状态前，对文字、图片和音频执行适用的内容安全检查。
- 检查中显示“正在准备分享”，不能先传播后假装未发生。
- 检查失败不删除个人原始 Moment。

### FR-SAFETY-002 举报

- **优先级**：P1
- 家庭成员可以从详情次级入口举报内容。
- 举报入口不需要像公开社区一样占据主界面。
- 处置记录与原始业务内容分离。

### FR-SAFETY-003 处置

- **优先级**：P1
- 平台可限制分享、隐藏家庭副本或冻结成员传播能力。
- 处置不能无审计地覆盖或删除用户个人原始数据。
- 用户应收到不暴露审核规则细节的清楚结果。

### FR-SAFETY-004 隐私最小化

- **优先级**：P0/P1
- 不收集验证血缘所需的身份证、户口资料。
- 不默认读取通讯录、精确位置或完整相册。
- 不使用人脸或声音做身份识别。
- 第三方 SDK、日志和分析不得上传媒体正文，除非有明确必要性和授权。

## 11. 空、错与数据保全

### FR-DATA-001 真实空状态

- **优先级**：P0
- 存储不存在或合法集合为空时显示真实空状态。
- 禁止生产路径自动生成 mock Moment。

### FR-DATA-002 损坏数据隔离

- **优先级**：P0；当前仓库已实现基础能力
- 非法记录不进入页面 Projection，但原文保留并进入 quarantine。
- 合法记录读写不得覆盖相邻非法记录。
- 顶层集合不是数组时禁止覆盖。

### FR-DATA-003 缺失媒体

- **优先级**：P0；当前仓库已实现基础能力
- Asset 缺失或失败不删除 Moment。
- 根据可靠类型显示“照片暂时无法显示”“声音暂时无法播放”或通用缺失状态。
- 无法推断类型时不得默认当成图片。

### FR-DATA-004 Moment 不存在

- **优先级**：P0；当前仓库已实现
- 返回稳定 not-found，不回退其他 Moment。

### FR-DATA-005 存储失败

- **优先级**：P0
- 读取失败与空数据分离。
- 写入失败保持旧数据不变。
- 任何恢复操作都必须幂等。

### FR-DATA-006 本地文件生命周期

- **优先级**：P0（尤其 iOS）
- 缓存目录中的媒体不能被视为长期 Asset。
- 应用必须将需要保留的文件移入持久目录并确认存在。
- 只有应用拥有且没有引用的文件可以清理。
- 系统相册原件不得删除。

## 12. Splash 与启动

### FR-START-001 启动职责

- **优先级**：P0
- Splash 只承担品牌识别和首页准备过渡，不是独立叙事页面。
- 首页日期和稳定背景属于持久层，Splash 退出后不得跳位或闪白。
- 不用动画掩盖存储迁移或读取失败。

### FR-START-002 首次与普通冷启动

- **优先级**：P0
- 首次启动可以包含一句简短说明。
- 普通冷启动只保留短品牌过渡或直接进入首页。
- 页面返回和 `onShow`/前台恢复不重播 Splash。

### FR-START-003 跳过和降级

- **优先级**：P0
- 用户触摸可以快速跳过且操作幂等。
- Reduce Motion 下直接进入首页或使用极短淡入。
- 低性能设备取消非必要位移与模糊。
- Splash 不得长时间拦截触摸。

## 13. 动效

### FR-MOTION-001 动效用途

- **优先级**：P1
- 只表达内容被留下、时间展开、过去重新出现和位置连续。
- 不用于随机漂浮、粒子背景、持续装饰或延迟保存。

### FR-MOTION-002 动效规格

- 每项动效必须记录触发条件、持续时间、缓动、位移/透明度范围、取消条件、低性能降级和触摸影响。
- 动效被取消后，状态必须直接收敛到最终 UI，不得停在半透明或不可操作状态。

### FR-MOTION-003 减少动态效果

- 尊重系统 Reduce Motion。
- 核心内容和操作不能依赖动画才能被发现或理解。

## 14. 无障碍、横屏与平板

### FR-A11Y-001 系统字号

- **优先级**：P0
- 支持系统 Dynamic Type/大字号。
- 超大字号下允许布局重排，不得截断主内容和关键操作。
- 不通过关闭字体缩放保持视觉稿。

### FR-A11Y-002 读屏

- **优先级**：P0
- 按钮具有明确名称、角色和状态。
- 图片无说明时不生成虚假描述；功能图标必须有可读名称。
- 录音状态、播放状态和错误应能被读屏感知。

### FR-A11Y-003 触控与认知负担

- **优先级**：P0
- 关键操作满足平台推荐的最小触控范围。
- 不把长按、滑动或隐藏手势作为唯一操作。
- 破坏性操作使用文字和确认，不只依赖颜色。
- 老年用户能够理解开始、停止、保存、返回和权限结果。

### FR-RESP-001 横屏与平板

- **优先级**：P0
- 支持手机横屏、iPad 和合理的分屏宽度。
- 控制正文行长和图片尺寸，不把手机单列无限拉宽。
- 安全区、键盘和底部操作在所有方向可达。
- 方向变化不能丢失草稿、播放状态或时间浏览位置。

## 15. 平台与架构要求

### FR-ARCH-001 页面数据来源

- **优先级**：P0
- 页面只消费 Service/Application 层提供的 ViewModel。
- 页面不得直接访问存储 key、拼装 lifecycle 或改写 Repository。

### FR-ARCH-002 新 Projection/ViewModel

- **优先级**：P0
- 允许为新首页、历史、创建和家庭 UI 新增 Projection/ViewModel。
- Projection 必须是确定性的；不得把随机布局保存成领域事实。
- ViewModel 不暴露不必要的 ownerId、revision、schemaVersion 和存储细节。

### FR-ARCH-003 双平台

- **优先级**：P0
- 微信小程序和 iOS 可以使用不同平台 Adapter。
- 纯领域规则、契约与投影可在验证后共享。
- 不把 WXML/WXSS、`wx.*` 或 iOS 文件 URI 写入共享领域层。

### FR-ARCH-004 iOS local-first

- **优先级**：P0（iOS）
- 使用 React Native + Expo Development Build + TypeScript。
- 结构化数据使用 SQLite，媒体使用持久文件系统。
- AsyncStorage/SecureStore 不能承担 Moment/Asset 主存储。
- 保存不依赖网络；未来同步失败不删除本地数据。

### FR-ARCH-005 微信迁移兼容

- **优先级**：P0
- 不重命名现有 `lampy_moments`、`lampy_assets`、`lampy_transmissions` 等 Key。
- 不删除旧 `lampy_lights`。
- 新 UI 不得绕过现有 validator、quarantine 和迁移幂等规则。

## 16. 非功能需求

### NFR-001 可靠性

- 核心保存路径必须具备幂等测试。
- 进程终止后草稿和已保存 Moment 可恢复。
- 单个媒体失败不扩大成整条记录失败。

### NFR-002 性能

- 首页和历史不加载不可见原图与完整音频。
- 动效不应持续占用 CPU/GPU。
- 必须在低性能设备上提供降级路径。
- 性能目标需在真实设备基线建立后量化。

### NFR-003 安全与隐私

- 最小权限、最小数据收集和明确可见范围。
- 日志不得包含完整用户文字、图片、音频、邀请 token 或可复用签名 URL。
- 客户端不得内置生产密钥。

### NFR-004 可测试性

- 领域、Repository、Projection 和媒体生命周期可独立测试。
- 时间、时区、ID 和文件系统可以注入测试替身。
- UI 自动化不得依赖生产 mock 数据。

### NFR-005 可维护性

- 新平台通过 Adapter 接入，不复制第二套领域语义。
- 决策、未验证项目和人工验收结果写入 `spec/`。
- 编译通过不能被报告为真机媒体流程通过。

## 17. 验收场景

### AC-001 首次使用

在真实空库启动，用户看到自然空首页；完成一条文字 Moment 后，首页出现该记录，重启后仍存在。

### AC-002 三张图片

用户选择三张图片并保存成功；尝试加入第四张时获得明确提示；重启后前三张仍可打开。

### AC-003 纯音频

用户点击开始、点击结束、试听并保存；强制结束 App 后重新打开详情，仍可播放同一段声音。

### AC-004 混合记录

用户输入文字、加入图片和录音，保存后首页、历史、详情指向同一 Moment，任一媒体失败不影响其余内容。

### AC-005 草稿恢复

用户输入内容后退出或杀死 App；重新进入创建页可继续同一草稿；不会生成重复 Moment。

### AC-006 权限拒绝

用户拒绝麦克风后仍可写文字和选图；已有草稿不丢失；页面提供克制的设置指引。

### AC-007 时间精度

创建 exact/day/month/year/unknown 五种时间精度记录；详情与历史不把 recordedAt 冒充 occurredAt。

### AC-008 缺失媒体

人为使一个 Asset 文件不可用；详情保留 Moment 文字及其他媒体，并显示与类型匹配的缺失文案。

### AC-009 找不到 Moment

用不存在或非法编码的 ID 打开详情；显示 not-found，不展示任何其他记录，不修改存储。

### AC-010 老年用户与大字号

在系统超大字号和 VoiceOver 下，用户仍能找到记录入口、开始/停止录音、保存并打开详情；没有只能靠图标猜测的关键操作。

### AC-011 横屏和平板

编辑过程中旋转设备或改变 iPad 分屏宽度；草稿、选中图片和录音状态不丢失，关键操作保持可见。

### AC-012 家庭邀请

邀请只能由明确用户接受；撤销或过期后不能加入；加入不自动公开个人历史；平台不声称验证了亲属关系。

### AC-013 家庭传递失败

分享过程中断网或重复点击；源 Moment 保持不变，只产生一次逻辑 Transmission，失败不显示为已送达。

### AC-014 家庭 UGC 处置

家庭可见内容在共享前进入安全检查；检查失败只阻止共享，不删除个人原始 Moment；成员可以从详情举报。
