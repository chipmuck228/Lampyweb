# Lampy 产品定义

> 文档状态：MVP 产品基线  
> 更新日期：2026-09-22  
> 适用范围：微信小程序与计划中的 iOS App  
> 本文定义产品价值、边界和决策原则，不替代领域模型与迁移规格。

## 1. 一句话定义

Lampy 是一个只属于自己和明确选择的家庭成员的生活记录空间。用户可以随手留下一句话、最多三张照片或一段声音，让今天普通的一点生活，在未来仍能被看见、听见和重新感受到。

内部产品定义：

> Lampy 帮助人保存那些不需要发布、却不应该消失的普通生活。

候选对外表达：

> 这里，留下自己的生活。

候选声音场景表达：

> 留下今天，以后还能听见。

以上展示文案仍是候选，不构成最终产品语言。现有“微光”“光罐”“点亮”“递灯”等词也不是不可改变的品牌资产。

## 2. 产品为什么存在

人的大部分生活并不适合发布：一句随口说的话、一张普通甚至不够清晰的照片、一段带着环境声的录音、一天中说不清楚的感受。这些内容在当下可能很小，经过时间后却可能成为理解自己和家人的重要线索。

社交平台主要帮助内容被表达、分发和互动；Lampy 关注的是内容能否被安全留下、长期积累，并在恰当的时候重新出现。

Lampy 不要求每一天精彩，也不替用户判断哪条生活更重要。它通过可靠保存、时间组织和克制回看，让时间自然产生意义。

## 3. 核心价值

### 3.1 直接价值：轻松留下

- 不要求写完整日记。
- 不要求先选择内容模板或记录类型。
- 一句话、一张照片或一段声音都能独立成立。
- 不要求包装、剪辑、配乐或解释给别人听。
- 普通、安静、不完整的内容同样可以保存。

### 3.2 时间价值：以后重新感受到

- 记录不会只是沉入列表底部。
- 用户可以从日、月、年的时间结构重新进入过去。
- 图片、文字和声音共同保留当时的语境。
- 记录时间、发生时间和导入时间保持诚实，不互相冒充。

### 3.3 家庭价值：在边界内理解彼此

- 用户可以主动把一条记录交给明确选择的家庭成员。
- “家庭”表示一个受邀请、私密、有限的共享空间，不表示 Lampy 已验证真实血缘或法律亲属关系。
- 分享不是扩大传播，而是把某段生活交给少数重要的人。
- 家庭成员关系不等于关注、粉丝或公开社交关系。

### 3.4 长期价值：形成私人生活档案

持续积累后，记录可以从多个角度重建一个人的日常：关注过什么、生活在怎样的环境、听到和经历过什么，以及一段时间里怎样生活。

在本人主动授权和清楚隐私边界下，它未来可能帮助家人理解一个人的生命经历。但这属于长期结果，不是当前产品入口；MVP 不采用遗产、告别、纪念馆或悲伤叙事。

## 4. 与社交平台的区别

| 维度 | 社交内容平台 | Lampy |
|---|---|---|
| 主要目的 | 表达、传播、互动 | 保存、积累、回看 |
| 默认观众 | 公众、关注者或兴趣人群 | 自己或明确选择的家庭成员 |
| 内容选择 | 值得发布的内容 | 不需要发布也值得留下的生活 |
| 成功反馈 | 播放、点赞、评论、关注 | 成功留下，并在未来仍可找回和理解 |
| 时间结构 | 持续刷新的推荐流 | 日、月、年逐渐沉积 |
| 内容处理 | 容易鼓励包装与表演 | 尊重原始文字、照片和声音 |
| 情绪倾向 | 容易放大精彩和积极表达 | 接受平静、琐碎、复杂和不确定 |
| 关系结构 | 关注关系和传播网络 | 私人空间中的授权关系 |
| 算法角色 | 排序并放大内容 | 不评价生活价值，只帮助找回 |

产品判断句：

> 社交平台帮助人分享生活，Lampy 帮助人留住生活。

任何新功能都应回答：它是在帮助用户留下自己的生活，还是在诱导用户制作给别人看的内容？如果主要服务后者，就不应进入 Lampy MVP。

## 5. 目标用户

### 5.1 主要用户

- 想记录生活但无法长期写日记的人。
- 不愿公开发布，却希望保存真实日常的人。
- 希望把少量生活交给家人，而不是建立公开社交账号的人。
- 看重照片与声音原始质感的人。

### 5.2 家庭用户

- 异地生活、希望理解彼此日常的家庭成员。
- 希望在低打扰条件下保存家庭生活的父母、成年子女和长辈。
- 希望共同保留某些普通时刻，但不需要群聊热度的人。

### 5.3 老年用户

老年人不是被采集、被纪念的对象，而应首先是拥有控制权的记录者或授权者。

支持两种平等的参与方式：

1. **自己记录**：通过一次点击开始/结束录音、拍一张照片或写一句话。
2. **家人协助**：家人帮助拍摄、录音或导入，但必须清楚呈现由谁记录、内容属于谁、谁可以查看，并避免冒充老人本人表达。

面向老人的日常界面仍然讲“今天的生活”，不以“以后留给儿女”制造压力。

## 6. MVP 范围

### 6.1 必须实现

1. 记录文字、图片和音频。
2. 支持手动输入、现场拍摄/录音，以及从手机资源导入图片。
3. 单条 Moment 最多三张图片、最多一段音频。
4. 支持纯文字、纯图片、纯音频和混合内容。
5. 支持草稿恢复、失败保全和应用重启后的数据恢复。
6. 首页先让用户看见最近生活。
7. 历史页承担日、月、年层面的整体积累。
8. 只读详情允许重新进入一条过去记录。
9. 仅支持“个人”和“家庭”两个可见范围概念。
10. 家庭通过邀请和主动接受建立，不验证真实亲属关系。
11. 家庭内分享需要明确授权、成员边界和内容安全机制。
12. 支持 iPhone、iPad、横屏和系统超大字号；微信小程序继续保留现有实现路径。

### 6.2 MVP 明确不需要

- `significance` 采集或展示主流程；字段可以为了历史兼容保留，但 UI 不要求填写。
- 陌生人、附近的人或随机接收。
- 公开主页、公开内容链接、关注关系。
- 点赞、评论、排行榜、热度、连续记录天数。
- AI 总结、自动判断内容价值或自动改写用户记录。
- 视频记录。
- 复杂编辑、滤镜、配乐和发布模板。
- 数字遗产、纪念馆、身后交付流程。
- 云端家庭相册或无限共享空间。
- 复杂 3D 和大面积装饰性动画。

## 7. “情绪”的重新定义

当前 `Moment.content.emotion` 已存在，但 MVP 不把情绪设计成心情打卡、正负分数或固定表情标签。

目标定义：

> 情绪是用户愿意为当时状态留下的一点补充语境，不是对一天的评价，也不是 Moment 是否值得保存的条件。

原则：

- 可选，不填写不影响保存。
- 不只允许积极情绪。
- 不统计“积极率”，不生成心理判断。
- 不用红黄绿、分数或连续曲线评价用户。
- 可以允许“不确定”“说不清”或用户自己的短语。
- 情绪不会改变记录排序、推荐权重或视觉大小。

具体输入方式和词汇表仍需后续产品语言阶段确认。

## 8. 核心体验原则

### 8.1 不表演

用户不需要让内容完整、精彩或适合公开传播。

### 8.2 不评价

没有热度、质量分、积极度、连续记录奖励或“错过一天”的惩罚文案。

### 8.3 不打扰

提醒应服务于未保存内容或明确请求，不以增长目的制造记录压力。

### 8.4 不丢失

任何媒体失败都不能导致整条 Moment 消失；页面失败不得覆盖或删除原始数据。

### 8.5 不伪造

记录时间不冒充发生时间；导入不冒充现场创建；本地发送意图不冒充真实送达；家人协助记录不冒充本人记录。

### 8.6 可长期使用

产品结构和视觉秩序必须在五年积累后仍然安静、清楚、可查找，而不是只适合制作一张漂亮截图。

## 9. UI 体验方向

目标是“精致的生活化”，不是“精致模板”。

- 内容与页面底色直接发生关系，而不是全部装进 Card。
- 日期成为时间结构，而不是卡片标签。
- 图片像生活留下的画面，而不是商品缩略图。
- 文字像当时留下的一句话，而不是数据库字段。
- 声音像当时环境的一部分，而不是普通媒体工具栏。
- 多条记录通过时间、内容比例、疏密和留白产生节奏。
- 不规则来自内容和时间，不来自随机数。
- 动效表达“轻轻留下、时间展开、过去重新出现”，不用于炫技。

应主动避免：统一圆角 Card、标准表单、普通 Tabs、悬浮发布按钮主导页面、暖色模板、毛玻璃、过量渐变、拟物手账、随机旋转和大面积 3D。

## 10. 老年人与无障碍原则

- 关键操作触控区域至少满足平台无障碍建议。
- 支持系统字号，不通过禁用缩放保护排版。
- 超大字号下关键操作和内容不能被截断。
- 重要功能不只依赖图标、颜色、滑动或长按。
- 录音优先采用“点一下开始、点一下结束”，并明确显示录制状态。
- 权限拒绝、误触、返回和中断都应可恢复。
- 重要结果使用直接、具体的语言，不要求理解抽象品牌词。
- 支持 VoiceOver/读屏语义和 Reduce Motion。
- 横屏和平板不只放大手机页面，应控制阅读行长并重新组织空间。

## 11. 家庭与隐私边界

Lampy 不认证血缘，只负责私人空间中的身份、邀请、授权、内容安全和访问边界。

- 成员通过邀请和主动接受加入。
- 邀请应可过期、撤销并限制重复使用。
- 不允许通过昵称、手机号或附近位置搜索陌生人。
- 家庭规模和账号加入数量应有限制。
- 成员可以退出、屏蔽和举报。
- 被移除或退出后，访问权限必须按明确规则失效。
- 每条内容需要明确的个人/家庭可见范围。
- 家庭共享内容需要文本、图片和音频的安全处理机制。
- 不提交亲属证明、户口信息等超出目的所需的敏感资料。

“谁记录”“内容关于谁”“谁拥有副本”“谁可查看”是不同概念，后续家庭领域模型必须分别表达。

## 12. 领域与数据边界

以下为已经确认、不可由 UI 随意改变的边界：

- Moment 是核心领域实体。
- Asset 独立存在，Moment 只保存 Asset ID。
- Transmission 是独立实体。
- 页面通过 Service 和 Projection 获取 ViewModel。
- UI 不直接修改底层存储。
- Moment 的 `occurredAt`、`recordedAt`、`importedAt` 语义分离。
- Asset 丢失或失败不会自动删除或隐藏 Moment。
- 指定 Moment 不存在时不能回退到其他记录。
- 当前详情页只读。
- 现有存储 Key、Repository、迁移和 quarantine 规则不得由展示层重命名或绕过。
- 当前 `local-user` 只是未登录 MVP 的过渡身份，不是家庭账号模型。
- 当前本地 Transmission 的 `sent` 只表示本地分享意图，不证明真实送达。

## 13. 平台策略

### 13.1 微信小程序

继续作为现有验证载体，保持 Moment V1 数据安全和迁移兼容。旧 Light Wall、Vault、Nearby 和“微光”展示语言可以逐步替换，但不能因此改坏领域数据。

### 13.2 iOS App

计划在同一仓库并行建立 React Native + Expo + TypeScript App，采用 local-first、SQLite 与持久文件存储。优先复用纯领域规则、Projection 契约和测试，不机械复用 WXML、WXSS 或 `wx.*`。

两个客户端可以共享产品与领域事实，但各自拥有平台 Adapter。任何共享代码抽取必须先证明不会破坏微信小程序。

## 14. 成功定义

MVP 不以公开内容量或互动量为核心成功指标。优先观察：

- 用户是否能在低负担下完成第一条真实记录。
- 只写、只拍、只录三种路径是否都能自然完成。
- 草稿、权限拒绝、媒体失败和重启后是否不丢内容。
- 用户是否愿意在未来重新打开过去记录。
- 历史内容增多后是否仍能找到某一天或某条记录。
- 家庭分享是否发生在明确授权和可信边界内。
- 老年用户是否能在少量协助后独立完成核心操作。

具体数据指标、观察周期和隐私友好的埋点方案尚未确定。

## 15. 当前仓库事实与产品目标的差距

以 2026-09-22 仓库 `main` 的 `5b5682c` 为基线：

- 已有 Moment、Asset、Transmission V1 领域模型与本地 Repository。
- 已有旧数据迁移、隔离损坏记录和只读详情能力。
- 已有首页 Light Wall、记录页、Vault、Nearby 和详情页。
- 当前记录页只支持一张图片和一段录音，不满足最多三图目标。
- 当前 `significance` 存在于领域字段，但页面未采集；MVP 应继续不要求。
- 当前“递灯”只记录本地分享意图，没有真实家庭送达闭环。
- 当前没有真实用户、家庭、成员资格、邀请和访问授权模型。
- 当前 `nearby` 不属于目标 MVP，应从目标导航与价值主张中退出。
- 当前空库会 seed mock lights，阻止真实空首页出现；该问题不能由视觉设计掩盖。
- 当前首页和历史投影仍使用光点、随机视觉分布和衰减隐喻，不是最终 UI 方向。
- 计划中的 iOS App 尚未存在于当前仓库基线。

## 16. 开放问题

以下问题未最终决定，不应由实现者自行假设：

1. 最终产品语言及“记录、历史、家庭、打开过去”的名称。
2. 情绪输入是自由短语、少量语义选项，还是二者结合。
3. 家庭内收到内容采用共享引用、接收副本，还是明确的双阶段接收协议。
4. 成员退出后，过去收到的副本如何保留。
5. 辅助老人记录时，记录者、内容主体和所有者如何建模。
6. 家庭成员数量、邀请有效期和加入家庭数量上限。
7. 云端部署地区、账号方式、内容安全供应链和数据保留期限。
8. 微信小程序与 iOS 是否共享同一云端账号和数据。
9. 视频何时进入后续版本。
10. 产品分析指标及其最小化采集方案。

## 17. 产品决策检查

每个新需求进入计划前必须回答：

1. 它是否帮助留下、理解或重新找到真实生活？
2. 它是否会诱导用户表演、比较或追求互动？
3. 没有它，MVP 的核心闭环是否仍然成立？
4. 它是否尊重个人与家庭边界？
5. 它是否会增加数据丢失、误授权或错误时间语义的风险？
6. 老年用户、横屏、平板和超大字号下是否仍可使用？
7. 五年积累后是否仍然成立？

只要功能主要服务公开传播、热度、评价或增长刺激，就不属于当前 Lampy。
